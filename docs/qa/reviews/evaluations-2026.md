## Data Pools feature evaluation (2026-07-30)

Date: 2026-07-30. Status: Evaluation complete; Tier A (correctness) remediation and the CSV import/export endpoints were applied the same day, the remaining Tier B and Tier C roadmap items are still open. Open items are tracked in [../DEFECTS.md](../DEFECTS.md) where scoped.

Scope: shared Data Pools end to end (REST API `/api/v1/data-pools*` and scenario bindings, storage, runtime consumption in the engine and distributed mode, importers, every dashboard surface touching pools). Method: three parallel code-exploration passes followed by direct source verification of every High-severity claim against the working tree.

**Verdict: a solid foundation, not yet production-usable at scale, with two selection strategies that silently violated their documented contract.** The control plane was well built (per-row optimistic concurrency, hierarchical project-to-pool locking, cross-project binding blocked at four layers, value-free audit events, docs matching the 11 implemented routes; runs snapshot pool contents at materialization, and distributed sharding of pool rows is provably disjoint). What undermined it: no bulk data path (one POST per row); a prototype-grade UI (raw JSON textarea, silent truncation at 100 rows, no pagination, no permission gating, zero tests); "unique" not unique at either level; and pools linked to scripts by an unvalidated alias string.

How it works: `SharedDataPool` / `SharedDataPoolRow` / `ScenarioDataPoolBinding` (`pkg/storage/storage.go`, `sqlite_datapools.go`); 11 endpoints in `pkg/api/handlers_data_pools.go`; bindings are `{pool_id, alias, access_mode, selection_strategy}` per scenario (`access_mode` only `read_only`; strategy one of sequential, random, unique, pop); at test creation `buildSharedDataSourcesLocked` flattens all rows of each bound pool into an inline CSV data source appended to every group's script; the engine has no pool concept (`DataProvider` serves `{{data.<alias>.<column>}}`; `ParameterRuntime` serves `{{param.<name>}}`, and only the former honors the binding's strategy); distributed runs ship the inline CSV to every generator.

Keep: storage CAS and lock ordering, four-layer cross-project authorization with identical 404s for missing vs cross-pool rows, fail-closed rejection of `read_write`/`consume` modes, run immutability from the inline snapshot, disjoint stride sharding with namespace-aware VU IDs, seedable deterministic `random` replay, docs in sync.

| ID | Sev | Finding |
|---|---|---|
| C1 | High | Parameter-level `selection:"unique"` is not unique across VUsers: it performs the same per-VUser index walk as `sequential` (`pkg/engine/parameters.go:365-411`); zero tests |
| C2 | High | Pool-level `unique` is `vuserID % shardRowCount`: one fixed row per VUser for the whole run and silent duplicates when VUsers exceed rows (`pkg/engine/data.go:358-369`) |
| C3 | High | The UI silently truncated pools at 100 rows and showed the page length as the total, while runs consume all rows |
| C4 | High | The scenario wizard hid bindings 2..N; clearing the pool select emitted `[]` (deleting every binding) and saving coerced `consume`/`read_write` to `read_only` (`TestHub.tsx`) |
| C5 | High | `ArchivedAt` was inert: archived pools still bound and executed; archive was one-way in the UI |
| C6 | High | Row `Status` was never filtered at materialization (`consumed`/`disabled` rows still fed runs) |
| C7 | High | API CAS protected the wrong window (against the value just loaded, ignoring the client's token), and the UI retried a 409 forever |
| M1-M8 | Med | `block_size`/`value_for_each_vuser` degrade in distributed runs (VU IDs offset by `ordinal x 2^31`); missing indexes on pool rows, bindings and project pools; alias silently mangled and its contract with script tokens unvalidated; `pop` exhaustion a silent nil; `Schema` write-only; no record of which rows a run consumed and `ReplayOptions.Seed` not reaching `ParameterRuntime`; unbounded rows/cells/bindings and N-fold shipping of the inline CSV; contract nits (unvalidated `DataSource.Strategy`, DELETE of a missing pool returns 200, unscoped list visible to any global viewer) |

Completeness gaps: API (no CSV upload/export/bulk insert, no `total`, no copy or archive/restore endpoint, no ETag contract, no importer producing pools because LoadRunner `.prm`/`.dat`, JMeter CSV Data Set Config, Postman and `paramize` all emit script-local sources, `DeleteScenarioDataPoolBinding` with no route, optional storage interface upgrades giving non-SQLite backends 501s); UX (raw JSON row editing though the script editor has a full grid, no rename/description/schema editing, no loading/busy/success states, execution plans requiring pasted pool UUIDs, no permission gating despite `view_data_pools`/`manage_data_pools`, no pool-to-parameter binding UX, dead hook methods, no open/edit action in the repository catalog, naming chaos across "Data Pools" / "Shared Data Pools" / "Reusable Data" / "Data" including a block-library collision, accessibility gaps, zero UI tests). Test coverage was strong for binding normalization, security, CAS, audit and DataProvider strategies and absent (pre-remediation) for parameter-level unique/random, end-to-end pool-to-engine paths, archived filtering, `inlineCSVFromDataPoolRows` edge cases, row status, `pop` exhaustion, `block_size` under distributed offsets and the pools UI.

LoadRunner parity snapshot: update policies, selection (sequential/random/unique), `same_line_as`, exhaustion policies, `start_row`, `block_size`, `value_for_each_vuser` and 12 parameter types were mapped from `.prm`; missing or divergent were true cross-VUser Unique (C1/C2), `auto_allocate_block_size`, parameter-level global consume, per-VU sequential walk (pool `sequential` is a shared group-wide cursor, closer to JMeter `shareMode=all`) and Unique's per-iteration block advance.

Roadmap (recommended):

- **Tier A, correctness (done 2026-07-30):** filter non-active rows and reject archived pools at bind, materialize, execution-plan and load-model validation; three missing indexes; honor client CAS tokens; wizard clearing removes only the visible binding; pre-run validation for `unique` (VUsers greater than active rows blocked) and `pop` (demand vs rows needs review).
- **Tier B, table stakes:** CSV import (done: multipart, append/replace, delimiter auto-detect, dry-run, 50 MiB route-scoped cap, transactional bulk insert) and export (done: streamed, status filter); `total` on row lists (done); still open: Settings grid row editor with pagination, rename/schema editing, archived filter and restore, 409 reload and permission gating; wizard multi-binding editor with alias hints and inline fit surfacing, pool select in execution plans, wiring the dead binding hooks; naming sweep to "Data Pools" (label only, keep the persisted `kind: 'data_pool'`).
- **Tier C, extensions (open):** `on_exhaustion` on bindings (on `ScenarioDataPoolBinding`, `dsl.DataSource` and engine `GetRow`, absent field keeps legacy behavior); storage-ref materialization for pools above about 1 MiB (needs a StorageRef branch in `openDataSourceReader`); consume-on-start row leasing as the smallest honest `consume`; promote an imported data source to a shared pool; run provenance (pool ID, name, row count, content hash) in the test manifest; smaller items (`{{data.*}}` token scan in the fit report, per-group bindings, pool duplicate, seed plumbing into `ParameterRuntime`).
- **Do not:** raise `MaxBodyBytes` through the generic data-pools policy fallback; bulk-import by looping `SaveDataPoolRow`; change engine `unique`/`pop` unconditionally (gate on an explicit `on_exhaustion`); put row contents in audit details; rename the persisted block-library kind; accept CSV uploads above about 50 MiB (engine reads cap at 50 MiB and distributed scripts at 64 MiB).

## LoadRunner runtime-settings import evaluation, ACME_RCI (2026-07-30)

Date: 2026-07-30. Status: Complete; retained as the runtime-settings accounting reference. Current behavior: [../../IMPORT_FIDELITY_AND_REPAIRS.md](../../IMPORT_FIDELITY_AND_REPAIRS.md).

Archive `ACME_RCI_Dummy.zip` (VuGen 24.3, Web HTTP/HTML, one `Action`, one `ACME_RCI` transaction, SOAP-over-HTTP `web_custom_request`); runtime settings `default.cfg` (9 sections, about 137 keys) and `default.usp` (run-logic tree and pacing) selected through the `.usr` `[CfgFiles]`/`[RunLogicFiles]` pointers. Question: are all Runtime Settings accounted for, translated correctly and displayed/editable in the Script Editor and the scenario override surfaces?

**Before the change:** the destination model and UI were largely ready, but the importer recognized only APEX-invented section/key names for several pages, so real VuGen archives imported those pages as zero settings, silently: `[ModemSpeed]` (Speed Simulation), `[FILTERS]` (Download Filters), real `[Streaming]` keys, `[Log] AutoLog`, `.usp RunLogicRunMode` (block scheduling), `.usp [Profile Actions]`/`RunLogicActionOrder` (action sequence), bare `[Java] UseExternalJVM/ExternalJREPath`, `*_extra_arg_N` spill rows (a `BrowserAcceptLanguage_extra_arg_2=en-us` lost behind `None`), and `.usr [Transactions]/[TransactionsOrder]`. The silent-drop default was the worst part: only an 18-entry allowlist warned, every other unmapped key vanished with no parity entry, and dropping a section raised the reported readiness score because it averaged only matched entries.

**Importer changes (`pkg/convert/enterprisearchive`):** real mappings for `[ModemSpeed]` (bps to Kbps; both toggles off is `max`), `[FILTERS]` (`allow_list`/`block_list`; both populated needs review), `AutoLog` to `log.on_error_only`, run-logic mode and action order as `compatibility_only` migration evidence (the engine does not consume them; custom orders need review), Java JDK selection, and transaction conservation checks; spill-row detection with a `request_headers` review finding for divergent values; error-handler run logic accounted for (`compatibility_only` for a real handler, `non_applicable` for the stock scaffold); a no-silent-drop completeness pass (`runtime_disposition.go`) classifying every key as `mapped`, `compatibility_only` or `non_applicable`, recorded per key at `metadata.import.preserved.runtime_setting_dispositions` and rolled up into `runtime_unmapped` and `runtime_non_applicable` parity entries so the score counts them; hyphenated download-filter hosts no longer corrupted by enum normalization.

**Dashboard changes:** a read-only Imported Source Runtime Settings section listing every preserved cfg/usp key with its source value and disposition badge (including non-selected profiles marked "preserved only"); the scenario override editor (`WebHttpTab`) now emits exactly the `pkg/dsl/validate.go` enums (it previously emitted `allow`/`block`, network `none`, streaming `none` and wrong content-check scopes), locked by test; the full per-group runtime editor is mounted for scenario-root defaults and the Create Test overrides panel as one shared component (and `java_vuser` joined the apply-to-groups field contract, which had dropped it silently); TLS client cert/key/CA paths and the Playwright User-Agent became editable in the Script Editor, `download_resources`/`capture_screenshots` became enum selects, and `web_runtime` sections show for every HTTP-transport protocol.

**Result for this archive:** every cfg key plus the `.usp` tree carries an explicit disposition (`TestGoldenVuGen24RealRuntimeSettings` enforces zero unclassified keys against the sanitized twin fixture `testdata/golden_web_http_html_vugen24`). Highlights: `RunLogicPaceType=Const` with 5 s to `pacing: fixed_interval, 5000 ms` (superseding cfg `IterationASAP`); `RunLogicNumOfIterations=1`; `AutomaticTransactions=1` to `per_action`; `ContinueOnError=1` plus `SnapshotOnErrorActive=1`; `ThinkTime Options=RECORDED` to recorded x1; `ConnectTimeout/ReceiveTimeout=500` to 500000 ms; `HTTPVer=1.1` plus `EnableHTTP2=1` as auto-negotiated H2 with 1.1 fallback; `TLS1.3` exact; IE 10 browser emulation with all five cache simulations; `[ModemSpeed]` both off to `max`; empty `[FILTERS]` as no filter; `LogExtended` plus parameter substitution. Two partial entries flagged for review with values preserved (`proxy`, where `ProxyNoLocal=1` has no exact `no_proxy` equivalent so the importer fails the proxy closed; `request_headers`, where the custom UA and the `_extra_arg_2` value diverge). Two compatibility-only run-ordering entries (an executable migration policy must include `compatibility_only` in `migration_block_statuses` so random/percentage scheduling, lifecycle omission and reordering stay review-gated). 44 active compatibility-only keys itemized in `runtime_unmapped` (for example `HttpErrorsAsWarnings`, `FailNonCriticalItem`, the NTLM/Kerberos block, `SupportCharset`, `Retry401ThinkTime`, `WebSyncRetry*`, `EnableIPCache`, PAC-proxy keys, `KeepAliveTimeout`, `NetBufSize`, `PageDownloadTimeout`, `ParseHtmlContentType`, `SSLVersionKey`, `[Streaming]` timing keys, the JavaScript-transport block) which affect source replay and need compatibility review. 97 non-applicable rows: VuGen authoring/recorder metadata, run-logic tree bookkeeping and inactive defaults.

Deliberate deviations: `UseDataFormatExtensions=1` was not mapped to `data_formatting.auto_detect` (LR enables a configured chain, APEX auto-detect actively decodes base64/gzip, which would invent behavior); `HTTPVer=1.1` plus `EnableHTTP2=1` needs no warning (the normal VuGen encoding of HTTP/2 enabled); `ProxyUseSame=0` with differing endpoints already fails closed. Evidence: `pkg/convert/enterprisearchive/testdata/golden_web_http_html_vugen24`, `runtime_vugen24_golden_test.go`, `runtime_execution_fidelity_test.go`, `runtime_disposition.go`, `pkg/api/acme_enterprise_archive_regression_test.go`, `dashboard/src/components/runtimeTabs/WebHttpTab.test.tsx`, `dashboard/src/components/ScriptRuntimeSettingsView.test.tsx`.

## LoadRunner runtime-settings import evaluation, ACME IAO (2026-09-22)

Date: 2026-09-22. Status: Complete; findings addressed in the importer and review panel, no open items. Current behavior: [../../IMPORT_FIDELITY_AND_REPAIRS.md](../../IMPORT_FIDELITY_AND_REPAIRS.md).

Evaluated `ACME_IAO_Azure_Akamai_2025.zip` with the local converter (source data only, target services not contacted; tests use synthetic actions and a sanitized copy of its runtime settings).

**Findings:** the import covered substantially more than the review panel suggested. Most "Source value unavailable" messages came from the panel requiring a one-to-one destination-field match even when the converter reported a whole configuration object or several fields (and expanding those objects manufactured rows for unrelated distribution fields): display and provenance bugs, not redaction. Random percentages of recorded think time were a real missing capability (the importer fell back to recorded timing with a partial-coverage finding for `Options=RANDOM`; `uniform.min_ms/max_ms` cannot substitute because each source delay needs its own scaled range; source semantics per the [OpenText runtime-settings reference](https://admhelp.microfocus.com/vugen/en/latest/help/WebHelp/Content/VuGen/166950_t_how_to_confugre_rts_manually.htm)). This archive sets `Options=NOTHINK`, its saved random bounds 50/150, factor 1 and disabled one-second cap are inactive, and its source has no `lr_think_time` calls, so percentage mode alone would add no waits; retain them as source information, do not claim active replay mappings.

Actual mappings (selected): `NOTHINK` to recorded with `ignore=true`; think-time bounds, factor and cap marked not applicable under NOTHINK (previously misclassified as mapped); `.usp` `Const` 5 s pacing to `fixed_interval` 5000 ms superseding cfg `IterationASAP`; iterations 1; `AutomaticTransactions=0` (explicit markers still execute); connect/receive timeout 500 to 500000 ms; `HTTPVer=1.1` plus `EnableHTTP2=1` as auto H2-preferred (empty DSL version intentional); keep-alive, redirect depth 10 and `MaxConnections=0` defaults omitted without being dropped; `KeepAliveTimeout=6000` as an explicit repair decision for `http.idle_timeout_ms` (importer supports positive whole seconds up to 3600, so this value is preserved without applying or clamping); custom proxy, custom User-Agent (winning over the dormant recorded identity), `BrowserAcceptEncoding`, cache toggles, extended logging (`AutoLog=0` disables error-only); `ContinueOnError=0` plus `lr_continue_on_error(1)` at `Action.c:13` to `continue_on_error=true` (source code supersedes cfg); `web_set_sockets_option("SSL_VERSION","TLS1.2")` at `Action.c:17` to exact TLS 1.2; modem selectors off to `max`; empty filters to none; `PageDownloadTimeout=500` to `http.page_timeout_ms=500000`; `DeleteCacheUnreferencedIterations=1` to `http.cache_max_unused_iterations=1`; `ParseHtmlContentType=TEXT` to `http.html_parse_mode=text`; `IPVersionPolicy=2` as an explicit repair decision (numeric encoding unverified, not guessed); `.usp` block scheduling and lifecycle order verified against the native sequential lifecycle.

**Changes made:** DSL mode `random_percentage` (`min_percent`/`max_percent`, a fresh sample per recorded delay, bounded `0 <= min <= max <= 10000`, invalid imported bounds need review) shared by load execution and diagnostic replay; C imports keep leading and consecutive source waits separate in every initial mode so later edits cannot combine samples or per-call caps (previously saved combined imports need re-importing); percentage controls in import review, script and scenario/group runtime settings with atomic apply and original source evidence kept; fixed grouped/multi-destination evidence matching, missing native logging aliases, absent-source rows and unrelated mode controls in the RTS panel (protected credential placeholders stay under Credentials); inactive think-time factor/percentage/cap values classified separately; `KeepAliveTimeout` import to `http.idle_timeout_ms` with seconds-to-ms conversion, editable review field and explicit handling of disabled reuse, malformed, conflicting and out-of-range values (the one-hour bound retained; the inaccurate "idle timeout is not configurable" note removed); authentication child options inactive when integrated authentication is explicitly disabled, `SupportCharset=None` inactive, prefetch timing inactive when prefetch simulation is off; streaming and synchronization defaults inactive when inspected C sources (native HTTP and SOAP, helpers and headers scanned) contain no such operation, with warnings kept for parse failures, external runners, mixed-language source, ambiguous macros and indirect references (proves absence in inspected source, not control-flow reachability); cfg pacing/iteration values superseded by an applied USP name that profile; sticky reference-table headers no longer cover the Details control.

Native compatibility implementation: whole-page deadlines, outgoing TCP IP-family selection (also for the proxy connection, though a proxy's own origin connection cannot be forced), cache aging by main iteration, HTML-discovery MIME modes and explicit cache/discovery MIME exclusion lists (at most 64 exact types, explicit recorded resource URLs stay eligible), in HTTP, SOAP and Java-over-HTTP transports, with script/group editor controls, review controls and source aliases, shared validation, schema generation and atomic edit/save coverage; imported page deadlines are positive whole seconds up to one hour (zero disables); cache aging zero disables and positive values are bounded to one million. Sequential compatibility is certified only against the selected profile and resolved C lifecycle declarations (external runners and custom trees remain review-only; the proof rejects extra or nested children, repeated init/end blocks, conflicts, missing files, mismatched action declarations and active custom error handlers; the engine still runs its native lifecycle and does not claim generic LoadRunner block-tree scheduling). Review fixes: obsolete cache entries evicted when a 200 or 304 changes to an excluded MIME type, teardown retained on replay iteration setup failure, deadline failures consistent with protocol evidence, cache counts normalized, lifecycle proofs refused for leaf-level scheduling overrides or unknown group controls, support matrix scoped to native HTTP, SOAP and Java-over-HTTP.

**Remaining coverage limits:** the selected cfg and usp contain 206 keys; per-key classification after the work is 56 mapped/consumed, 9 compatibility-only and 141 not applicable (previous pass 49, 16 and 141). These are accounting counts, not a replay-fidelity score; `KeepAliveTimeout` and `IPVersionPolicy` become dedicated partial repair entries whose source values were not applied. The nine remaining compatibility-only keys are `IgnoreContentCachingTypes`, `KeepNonTextMimeType`, `MaxErrorMatchesAsERRORS`, `MaxSelfMetaRefreshCount`, `NetBufSize`, `ResetContext`, `SSLVersionKey`, `WebSocketCallBackTimerIntervalMS` and `ZlibHeadersInCompressedRequestBody` (the two cache/MIME switches are not verified enough to translate automatically). The archive's 6000 s idle timeout exceeds APEX's one-hour bound ([OpenText documents the source timeout in seconds](https://admhelp.microfocus.com/lre/en/26.1/online_help/Content/PC/ui_runtime_settings_ip_preferences.htm)); accepting it would need a separate resource-limit change. General control-flow reachability, runtime-loaded code and complete source-code override accounting were beyond this pass; percentage execution covers native DSL think-time waits only (external runners implementing their own waits, such as an external Java Vuser process, are not extended, and dynamic C think-time expressions still need review). Semantics for page timeouts, cache aging and HTML parsing were checked against the [OpenText runtime preferences reference](https://admhelp.microfocus.com/lre/en/26.1-26.3/online_help/Content/PC/ui_runtime_settings_ip_preferences.htm); the archive's numeric IP enum and two MIME/cache switches stay unverified and configurable in review.
