## Static findings by entry point

Every entry point, the parser and the disk parser report exactly the fixture's static findings (`validateScript`), in order. Routes that refuse a script answer `400` with them, and validation routes answer `200` with them. Debug and replay routes judge the copy a session executes, with the submitted JVM arguments in place of the sentinels that mask them there; a finding only that copy has (a recorded resource URL whose credential it masks cannot be executed) is contextual, classified apart and covered by `TestTransientReplayRefusesAMaskedRecordedResourceURL`. Routes that would execute a clean script are exercised with invalid fixtures only. Content that cannot be stored as an ordinary script (a credential-bearing JVM argument) is refused by create and update with a storage-safety message that leads with its findings. A credential-bearing Java Vuser import is stored only through the authoring-session approval of its import, which stores the copy `preparePersistentImportedLibraryScript` prepares, so the stored routes are covered for it by the import saves' check below, which prepares the copy the same way and runs the stored validator the stored routes use. Contextual runtime, install, policy and approval outcomes are not static findings and are classified apart.
