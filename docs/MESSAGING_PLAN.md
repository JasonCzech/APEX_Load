## Architecture constraints and design decisions

- A new protocol lives in `pkg/protocol/<name>/`, implements `pkg/protocol.Protocol`, self-registers via `init() -> protocol.Register(name, factory)`, and is blank-imported by `cmd/generator`, `cmd/controller` and (a subset) `cmd/apexctl`. Real execution runs on generator pods.
- Real adapters follow a build-tag seam: a `//go:build <tag>_real` file plus a fail-closed default stub, and a `pkg/dsl/capabilities_<x>_{real,default}.go` availability helper that the validator consults so non-mock scripts only validate when the adapter is compiled in.
- The results pipeline is protocol-neutral (`protocol.ServerTelemetry` to `ServerTelemetrySummary`/`ProtocolSummary` to proto/distributed merge to dashboard). An adapter that fills `ServerTelemetry` inherits throughput, message latency, consumer lag, payload sizing, throughput-gap SLA and the broker-pressure analyzer with no new results code.
- Build once, reuse everywhere: unified result model with reliability counters; request-reply correlation with safe requeue; a generic AMQP 1.0 layer factored from the Solace adapter; schema-registry serde (Confluent wire format); one consumer-lag/queue-depth/backlog surface; true dead-letter/redelivery counts; an ack/transaction state machine replacing the no-op `jms_ack`/`jms_commit`/`jms_rollback`; catalog enums and declared runtime params; messaging SLA/goal evaluation; a higher-fidelity mock broker (fan-out, partitions, groups, ack/redelivery, TTL).
- Generated artifacts must be refreshed after catalog or route changes: `go generate ./pkg/dsl` (`docs/dsl.schema.json`, `docs/DSL_ACTION_REFERENCE.md`, freshness enforced by `pkg/dsl/schemagen`) and `go generate ./pkg/api` (`docs/swagger.yaml`, `TestSwaggerYAMLIsFresh`).

## P2.5 IBM MQ native adapter (open)

Goal: a native-MQI transport (`MQCONNX`, `MQOPEN`, `MQPUT`/`MQPUT1`/`MQGET`, `MQCMIT`/`MQBACK`, `MQSUB`, `MQDISC`) opt-in behind `-tags ibmmq_real`, fail-closed by default, with MQMD control (persistence, priority, expiry, MsgId/CorrelId as `MQBYTE24`), RFH2-vs-MQMD property split, SVRCONN/CCDT/CipherSpec/MQCSP connectivity, backout/DLQ taxonomy, and validate-gate parity with Solace and Service Bus.

Design: mirror the real/default pair with `newIbmMqAdapter(cfg) brokerAdapter` in `//go:build ibmmq_real` and `!ibmmq_real` files (default returns an unavailable adapter; real uses `github.com/ibm-messaging/mq-golang/v5/ibmmq`, cgo against the MQ C client redistributable). Map the five `brokerAdapter` methods: Publish to `MQPUT1`/`MQPUT`, Consume to `MQGET` with `MQGMO` (wait interval, browse, syncpoint plus commit/backout), RequestReply to `MQPUT` with `ReplyToQ` then a correlated `MQGET`. Surface `MQMD.PutDate/PutTime`, backout count and resolved queue manager in `result.Extractions`. Rejected: a sidecar JMS bridge (native MQI gives true MQMD fidelity and lower latency) and a pure-Go MQ reimplementation (no supported library).

DSL and catalog: no new action types; add a `jms-ibmmq` protocol alias next to `jms-solace` in `catalog.go`, MQMD fields `mq_persistence` (`persistent|non_persistent|as_queue`), `mq_priority` (0-9), `mq_expiry_ms`, `mq_msg_id`, `mq_correl_id`, `mq_format`, `mq_reply_to_qmgr`, and config keys `mq_queue_manager`, `mq_channel`, `mq_conn_name`, `mq_ccdt_url`, `mq_cipher_spec`, `mq_backout_queue`, `mq_backout_threshold`, `mq_property_style` (`rfh2|mqmd`). Extend `config` and `message` in `pkg/protocol/jms/jms.go` (an `mqMessageDescriptor` carrying persistence, priority, expiry, MsgID, CorrelID, format, backout count, reply-to qmgr); add `IbmMqJMSRealAdapterAvailable()` in `pkg/dsl/capabilities_ibmmq_{real,default}.go`; add `isIbmMqJMSScript()` and an availability issue in `pkg/dsl/validate.go` parallel to the Service Bus check; plumb keys in `pkg/engine/config_protocols.go`; update `go.mod`. Real files: `pkg/protocol/jms/realadapter_ibmmq.go` and `realadapter_ibmmq_default.go`.

Build and CI: an `ibmmq_real` lane with the MQ client provisioned in the runner image; the cgo-free default lane must keep compiling. Integration via testcontainers `icr.io/ibm-messaging/mq` (`DEV.QUEUE.1`, `DEV.APP.SVRCONN`) covering put/get, persistence/priority/expiry, MsgId/CorrelId, syncpoint commit/backout, browse and DLQ/backout routing.

Acceptance: `-tags ibmmq_real` builds while default stays fail-closed without the MQ SDK; `mock:false` validates only when the adapter is available; MQPUT/MQGET round-trip against a real queue manager honors MQMD fields; syncpoint and backout-threshold routing verified; `go generate ./pkg/dsl` clean; `go test ./...` and `go test -tags ibmmq_real ./...` green. Effort XL; depends on the shared ack/session state (P1.2, landed), catalog parity (P1.4, landed) and JMS semantics (P2.3, landed). Risks: cgo and the MQ C client complicate CI, images and cross-compilation (linux/amd64 generator pods only); `MQBYTE24` semantics and RFH2 vs MQMD property placement are interop foot-guns; container image licensing and startup time; `jms_ack`/`jms_commit`/`jms_rollback` must be made real for MQ or documented as not wired.

## P2.6 Solace native SMF transport (open)

Goal: a native SMF transport alongside the AMQP adapter: direct vs guaranteed messaging with a publisher-ack window and bounded consumer flow; `*`/`>` wildcard subscriptions and topic-to-queue mapping; partitioned queues by partition key; exclusive vs non-exclusive access; DMQ plus max-redelivery (0-255); replay (all, msg-id, timestamp); Message-VPN, TLS and compression. Build-tagged, fail-closed by default.

Design: add `pkg/protocol/jms/solace_smf.go` (`//go:build jms_solace_smf`) implementing `brokerAdapter` with the official `solace.dev/go/messaging` SDK, plus `solace_smf_default.go` (`!jms_solace_smf`) with an `unavailableSolaceSMFAdapter` and `SolaceSMFRealAdapterAvailable()`. Stay inside the JMS package (Solace is already a JMS provider and the telemetry plumbing is JMS-shaped). Extend `selectAdapter` so `provider==solace` with `properties["transport"]=="smf"` returns `newSolaceSMFAdapter(cfg)`; AMQP stays the default and `normalizedBrokerURL` stays AMQP-only while the SMF path accepts `tcp(s)://` and `smf(s)://`. Publisher acks satisfy `jms_publish`; persistent-mode consumer ack makes `jms_ack` real for this path, closing the parsed-but-ignored `delivery_mode`/`acknowledgement` gap. Rejected: a native SMF C wrapper (cgo in generator pods) and a new protocol name (breaks catalog, import and dashboard reuse).

DSL and catalog (`pkg/dsl/catalog_jms.go`): on `jms_publish` add `params.delivery_mode` (`direct|persistent`), `params.partition_key`, `params.dmq_eligible`, `params.ttl_ms`; on `jms_consume` add `params.access_type` (`exclusive|nonexclusive`), `params.max_redelivery` (0-255), `params.flow_window`, `params.replay` (`none|all|msg-id|timestamp`), `params.replay_from`. Config keys: `jms_transport`, `jms_publisher_ack_window`, `jms_compression` (1-9), `jms_replay`, `jms_replay_from`. Validation in `validateJMSScriptIssues`: redelivery range, replay_from required for msg-id/timestamp, SMF availability gate. Telemetry: add `RedeliveryCount` handling from SMF delivery count (already in the shared counters), and extractions `jms_redelivered`, `solace_partition_key`, `solace_replay_offset`.

Build and CI: add `solace.dev/go/messaging` to `go.mod`; tags `jms_solace_smf` and `jms_solace_smf_integration`; a lane in the `protocol-tags` job of `.github/workflows/ci.yml`; integration against a `solace/solace-pubsub-standard` testcontainer (wildcards, topic-to-queue, partition affinity, exclusivity, DMQ, replay, TLS/VPN). Acceptance mirrors the goal list plus a clear fail-closed error text ("build with -tags jms_solace_smf") in the default build. Effort XL. Risks: confirm the SDK is CGO-free for the linux/amd64 generator image, otherwise fall back to the existing sidecar adapter path and revisit the build-tag design; replay and DMQ need broker-side provisioning in the harness; partitioned queues need a recent broker in the testcontainer; ack/flow-window tuning interacts with VUser density targets.

## Azure Event Hubs design record

Two faces, both landed producer-first:

- Kafka endpoint (`{namespace}.servicebus.windows.net:9093`, TLS mandatory, SASL `PLAIN` with username `$ConnectionString` or `OAUTHBEARER` with an AAD token, 1 MB message cap) is a `profile: "eventhubs"` on the existing `kafka` protocol. It forces TLS, wires PLAIN/OAUTHBEARER and guards the message cap, reusing the whole metrics/import/dashboard pipeline.
- Native AMQP is a dedicated `eventhubs` protocol behind `eventhubs_real`, cloning the JMS provider-adapter pattern (`selectAdapter()`, pooling as in `realadapter_servicebus.go`, paired real/default files). It hosts partition keys, AMQP credit metrics and Capture parity.

Locked decisions: auth by connection string (SAS) and AAD/workload identity (native gets AAD via `pkg/engine/azure_token.go`; the Kafka endpoint needed OAUTHBEARER, delivered by EH.2); build-tag opt-in and mock by default; import from the AsyncAPI Event Hubs binding and Capture files (ARM/Bicep dropped); metrics producer-first aggregate plus per-partition produce throughput/bytes (skew and hot-partition detection, not consumer lag); role is producer plus a read-only observer probe measuring E2E produce-to-consume latency and downstream backlog. Headline producer metrics: publish throughput, ack latency, throttling/429 `ServerBusy`, ingress bytes/sec, per-partition skew; probe-derived E2E latency and backlog. Kafka EOS on Event Hubs is Premium/Dedicated preview-only, so scope transactions as broker-capability-gated.

Deployment: `deployments/azure/terraform/eventhubs.tf` (namespace, hub, Send and Listen rules with connection strings in Key Vault, Data Sender/Receiver role assignments) exists; the AKS configmap env vars `APEXLOAD_EVENTHUBS_AUTH` and `APEXLOAD_EVENTHUBS_PROBE_CONSUMER_GROUP`, Helm values/templates examples, and `docs/EVENT_HUBS_HOWTO.md` are the unbuilt remainder. New dependencies used: `azeventhubs` (native AMQP) and `github.com/hamba/avro/v2` (Capture decode). Key reuse points: `pkg/protocol/kafka/realclient_{default,franz}.go`, `pkg/protocol/jms/jms.go` `selectAdapter()`, `pkg/engine/azure_token.go`, `pkg/dsl/capabilities_servicebus_{real,default}.go`, `pkg/api/distributed_metrics.go`, `pkg/api/import_paramize.go`.

## Kafka plugin and AsyncAPI design record (implemented)

Two additive deliverables: a Kafka protocol plugin (`pkg/protocol/kafka`, direct-execution protocol modeled on JMS, required core) and an AsyncAPI converter (`pkg/convert/asyncapi`, the event-streaming analog of the OpenAPI importer, the only importer that legitimately emits Kafka DSL). Existing importers are not reused for Kafka. Kafka is authored directly, not recorded.

Opt-in real adapter (`github.com/twmb/franz-go`, pure Go, no cgo): `go build -tags kafka_real ./cmd/generator ./cmd/controller ./cmd/apexctl`. With the tag, `config.kafka.mock: false` uses the franz client (SASL PLAIN/SCRAM-256/SCRAM-512/OAUTHBEARER, TLS with insecure/client cert/CA, acks, compression, consumer groups, produce/consume/request-reply/commit). The seam is `newRealClient(config)` in `realclient_default.go` (unavailable stub) versus `realclient_franz.go`. Live-broker test: `KAFKA_BROKERS=localhost:9092 go test -tags "kafka_real kafka_integration" ./pkg/protocol/kafka/...`. Default `go test ./...` exercises only the in-memory mock.

Runtime surface: actions `kafka_produce`, `kafka_consume`, `kafka_request_reply` (correlation header then reply topic), `kafka_commit`, `kafka_seek`. Config keys flatten from `ScriptConfig.Kafka` (`KafkaConfig`: brokers, security_protocol `plaintext|ssl|sasl_ssl|sasl_plaintext`, sasl_mechanism, sasl username/password/`sasl_password_secret`, tls, client_id, consumer_group, topic, acks `none|leader|all`, compression `none|gzip|snappy|lz4|zstd`, partition_strategy `key-hash|round-robin|explicit`, auto_offset_reset, timeout_ms, properties, mock) to `kafka_*` keys in `pkg/engine/config.go`; `kafka_sasl_password_secret` uses the existing secret resolver. Extractors: body (json/regex), header, key, partition, offset, correlation_id. Assertions: `message_received`, `body_contains`, `header_equals`, `key_equals`, `partition_equals`, `offset_advanced`, `correlation_match`, `consumer_lag_below`, `response_time_ms`. Result enrichment reuses existing fields: `DependencyType` `kafka_topic`/`kafka_consumer_group`, `DependencyTarget` topic, extractions `kafka_partition|offset|key|timestamp|consumer_lag`. Validation is `validateKafkaScriptIssues` (broker required, enum checks, topic present) and `kafka` is exempt from `base_url`.

AsyncAPI converter: parses 2.x and 3.x (JSON/YAML); servers map to brokers and `security_protocol`; channels to topics (kafka binding for partition/key); send/publish to `kafka_produce`, receive/subscribe to `kafka_consume`, reply/correlationId to `kafka_request_reply`; payload schemas sampled to bodies with data-source review notes. Options: `script_name`, `brokers`, `operation_ids`/`channels`, `include_assertions`, `default_think_time_ms`. Routes: `POST /api/v1/scripts/import/asyncapi` and `GET /api/v1/scripts/import/asyncapi/support-matrix`. Dashboard: `asyncapi` kind in `ProtocolAssetImport.tsx`, `AsyncAPIImportResult` types, and a Kafka script starter in the Script Builder. Support matrix marks Kafka binding supported; Avro/Protobuf partial; MQTT/AMQP/WebSocket bindings out of scope or routed to review-only/`jms-solace`.

Open risks carried forward: (1) confirm the SSRF/egress allow-list guard intercepts raw `host:port` broker dials in `APEXLOAD_ENV=production`, not just HTTP URLs; (2) consumer-group semantics under load (many VUser goroutines sharing a group cause rebalances; per-VUser producer with configurable consumer-group sharing); (3) Schema Registry/Avro/Protobuf payloads in AsyncAPI specs remain a documented partial; (4) franz-go's effect on generator image size; (5) redact broker URLs with inline credentials in evidence (`BuildProtocolEvidence`).

- Event Hubs end-to-end mock run: `apexctl run` with an `eventhubs` producer script (`mock:true`) plus the observer probe, and a `kafka` script with `profile:eventhubs`; confirm throughput, ack latency, simulated throttling, per-partition distribution and probe E2E latency in `GET /api/v1/tests/{id}/metrics`. - Open decisions: which real adapters ship in the default generator image versus opt-in images (the default image must keep failing closed on non-mock messaging); IBM MQ native MQI (cgo) versus a pure-Go REST/AMQP fallback; Solace SMF via a cgo SDK versus staying on AMQP.
