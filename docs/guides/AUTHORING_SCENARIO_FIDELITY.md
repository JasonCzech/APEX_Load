# Scenario and queued-run authoring fidelity

This slice preserves scenario and queued-run authoring fidelity. The linked review records exact source, review findings and qualification results. Opaque scenario content revisions and the broader shared authoring owner remain separate AUTH-1 work.

An unrelated scenario edit preserves the root and group Results and WebSocket sections, named workload shape, workload configuration, group timing and transaction response-time SLA. An absent section inherits. A present empty section is a whole-section replacement. Explicit false and zero values retain the existing runtime contract. Run-only clear operations remove the selected override so the lower layer applies. These distinctions do not introduce new protocol measurements.

Changing workload shape replaces demand bounds and workload configuration. Existing SLA, error, transaction and monitor guardrails survive unless the selected shape or template explicitly replaces that field. An explicitly empty rule array clears those rules. The runtime continues to decide which guardrails apply in each execution mode; retaining authored settings does not enable new measurements or change that policy.

Results copied from a script can contain CSV exports or property analytics without exchange-capture configuration. Editing exchange capture in a queued group's Runtime Settings keeps those sibling settings. The WebSocket callback interval admits zero according to the existing execution contract. Transaction SLA inputs use seconds and permit the positive fractional values already accepted by the API; saving validates strict positivity, including sub-millisecond thresholds.

To create a revised queued run, open its Command Center and choose **Create revised queued copy**. The action requires the existing manage-tests permission and an actual, unstarted QUEUED source in the current project. The controller remains authoritative if the source starts while the form is open. A fresh canonical read captures the source before editing. Save creates a new queued run and selects it; the original stays unchanged. Navigating, changing project or losing permission retires the form and its late callbacks. Advanced run details keep their existing inspection-only architecture.

A revised copy retains the source's Elastic log-capture and Dynatrace SaaS-capture connection IDs. A missing connection or unavailable readiness check keeps that selection visible and requires review before creation. Choose **Off** explicitly to remove a capture. Changing project clears those project-scoped selections; reopening or refreshing the same project does not. The controller rechecks connection eligibility when it creates the copy.

Clearing the last guardrail from a source with an authored goal configuration submits an explicit empty configuration, so the copy does not inherit the cleared guardrail. A source with no goal configuration keeps it absent. Existing goal settings are copied without adding new-draft defaults.

If you edit the form while creation is pending, a successful response shows the created run ID and keeps your later edits open with their unsaved-change protection. It does not create another copy automatically. An unchanged submitted draft releases its own guard and selects the new run; it cannot release another editor's guard.

A revised iteration-terminated source keeps **All per-user iterations** as its completion mode, its finite iteration settings and its allowed empty duration. Completion mode is read-only in this copy workflow; the duration input is disabled for iteration completion, and the controller validates the resulting script and runtime counts.

Clearing a source's nonempty Global Start Delay sends the canonical `0s` clear. The controller accepts this value only after admitting the matching, unstarted queued source; ordinary and saved-scenario delays remain strictly positive when present. Positive start delays remain supported for duration and iteration completion. The clear requires the same supported completion mode as the source and cannot convert it. Clearing the last root runtime override sends an empty root object when the source originally had one. Originally absent delay/runtime fields stay absent, and present empty runtime sections keep their separate replacement semantics. Supplied groups continue to follow the existing group clearing and root-inheritance rules.

The form's Create action and a browser history navigation guard share one in-flight creation operation. Choosing **Save changes** while creation is pending joins that submitted snapshot; it cannot submit a second copy from later edits. This does not add durable request idempotency across reloads or controllers.

New Test group edits and revised copies retain authored start offsets, ramp-up/down, stages, initialization, runtime overrides and per-group transaction SLA. A queued copy also retains the actual workload configuration. This slice does not add a named-shape identifier to run metadata.

Library scenario exports use the same portable content projection as local link hashing. Historical default duration mode and omitted empty shape retain their existing hashes. Nondefault termination mode and group SLA now transfer and participate in hashes. Older links that omitted those nondefault fields can correctly report a local change or conflict; the importer does not accept a weaker hash that erases the fields. A complete imported snapshot materializes an absent portable shape as an explicit clear only after the supplied portable hash is validated. Ordinary scenario updates with an absent shape continue to preserve the current value. Rollback and owned recovery use complete, separately owned snapshots.
