<a id="feature-completion-authoring-revision-2026-10-05--implemented-boundary"></a>

### Implemented boundary

Schema release 37 adds a persisted opaque script-content nonce. Authored script and application/release placement changes advance it atomically across normal and conditional saves, synchronization, imports, source activation and ID repair. Current script, nonce and placement are read from one coherent transaction. Display context and timestamp-only updates do not supply edit authority. All published migration releases 1–36 and their fingerprints remain unchanged; release 37 is `durable-script-content-revision`, fingerprint `d741b8384d281d84172d60b888a72228892173bbbc96d4f04a0e480cc1e9b745`.

The versioned authoring read exposes a deterministic authored representation and its strong ETag, with project ownership checked before precondition details. Ordinary PUT accepts one exact tag, checks it before credential reconciliation and within the final CAS, returns 412 for a stale edit and rejects malformed/wildcard/weak/list tags. A strict project policy rejects missing tags with 428. Store-backed compatibility writes require a durable intent and outcome and remain explicitly unconditioned. Ambiguous commit or missing outcome audit retains a reload-required 503 response rather than claiming rollback or enabling automatic overwrite.

Ordinary POST is create-only, preserving supplied primary-ID semantics. Exact primary IDs take precedence over display aliases through conditioned read/write. RefKey case normalization and cross-replica lookup use durable state. Existing protected import/approval receipt semantics, project boundaries, secret-reference mutation fences and publication visibility remain enforced. Strong ETags apply only to the authoring representation; enriched responses carry the coherent final projection and revision without an enriched-body ETag. See the [operator/API workflow](../../SCRIPT_LIFECYCLE.md#durable-script-authoring-saves).
