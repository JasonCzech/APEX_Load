### Consistency contract (the spec)

Preserve brand assets, themes, authorization, data integrity and workflows.

- **Hierarchy:** stable page header (title and effective scope left, one primary action right, overflow menu). Four navigation types: global (stable sidebar, named collapse), page (shared component, URL and back preserved), content tabs (arrow/Home/End, associated panels), wizard steps (numbered, validation state, stable Back/Next footer, draft save visibly secondary). Retire Original/v2 command-center choices.
- **Dialogs:** shared `Dialog` shell, compact/form/workbench (about 420/640/1040px, viewport-capped) plus confirmation; portal outside transformed containers, one layering scale, backdrop token, labelled close, scrollable body, stable footer, full-screen at narrow widths. Action-specific verbs (Create project, Delete user), primary last, safe dismissal. Deliberate initial focus, contained Tab, Escape for the topmost, guarded dirty dismissal, return focus to a surviving opener or named fallback; no re-enabled mutating action in flight; failed saves keep edits.
- **Context panels:** shared `ContextPanel`/`PanelToggle`, directional icon in the header, labels like "Collapse user details", `aria-expanded`/`aria-controls`, visible collapsed name, preserved state, overlay or after-task placement at narrow widths.
- **Libraries and tables:** one `LibraryToolbar` and table family (search first, essential filters, disclosure, creation, pagination); name/reference, health and main action visible at narrow widths; consistent More menu and contextual bulk bar; distinguish loading, empty, no matches, unavailable and failure; calendar agenda view when seven columns do not fit.
- **Forms:** shared `FormField`, help, validation and footer; explicit save model (immediate, staged, resource editor); a saved state looks like status; navigation prefills are not edits; save draft distinct from Next and execution.
- **Feedback and tokens:** one status vocabulary (queued, reserved, running, paused, completed, failed, aborted for execution; acceptance and evidence separate; unavailable is not zero, not assessed is not passed); 4/8/12/16/24/32px spacing; restrained pills; live-region announcements; operator language instead of internal keys.

Migration batches with gates: (1) dialog shell, Test Notes, focus, confirmations; (2) panel controls and responsive inspectors; (3) tabs, headers, library actions, scope; (4) forms, save state, feedback; (5) density, typography, themes. Do not migrate business logic into primitives; document exceptions for code editors, report documents and calendars.

### Audit

Local application (dev Admin, dark theme, build `v0.0.0-20260908152900-8a33cf69cab8+dirty`), primary run `45m Mixed User Group Synthetic` (LOC-RUN-20260620-008) compared with LOC-RUN-20260620-007, both Imported Legacy; findings on these historical records must not be generalized to new runs. **The reporting experience had substantial analytical capability but lacked one authoritative result, one consistent metric vocabulary and one clear operator journey.** No code or run data changed.

| Pri | Problem | Required change |
|---|---|---|
| P1 | An unassessed run labelled SLA Passed | One acceptance state across results, preview and exports; no criteria stays Not assessed |
| P1 | Different populations and missing values looked comparable | Distinguish requests/actions, named transactions and legacy records; carry population, window, sample count and availability; Not available / No samples, never misleading zeros |
| P1 | Post-run entry led to overlapping destinations | View results primary; historical snapshot secondary |
| P2 | Export choices repeated in several places | One Export action with audience, format, commentary; raw downloads under Evidence |
| P2 | Comparison conventions differed | One explicit baseline picker showing why it was chosen |

Proposed structure: one completed-run workspace (Summary, Performance, Diagnostics, Evidence) with Compare and Export in the header; comparison as a mode of that workspace; Executive/Technical/Audit as output presets over one evidence and acceptance model, read-only by default with an explicit Edit commentary mode showing derived and analyst assessments side by side. Limits: no measured contrast, keyboard or screen-reader test; PDF/HTML outputs not generated; failed-run and no-archive paths not completed.

### Implementation and review

Summary, Performance, Diagnostics and Evidence replaced the competing destinations; Compare and Export are header actions; the execution snapshot is secondary; the explicit feature-flag opt-out and old deep links remain compatible.

| Finding | Implemented change |
|---|---|
| Contradictory acceptance | Shared computed assessment in results and preview; analyst commentary cannot replace it |
| Mixed populations and false zeros | Explicit action, named-transaction and legacy populations with sample counts and whole-run scope; absent percentiles and empty baselines stay unavailable; tiny errors keep nonzero notation; no fabricated sparklines; narratives and documents follow the same rules |
| Competing destinations | View results is the primary library/dashboard action and opens the consolidated workspace |
| Repeated exports | One audience/format workflow with read-only preview and explicit Edit commentary |
| Inconsistent comparison | Explicit completed-baseline picker, no automatic pinning, context warnings, elapsed-time alignment, filter-preserving diagnostic comparison, release-trend labelled as prior-run comparison |

Review fixes: missing-data sparklines, baseline curves beyond their interval, stale report/baseline state, lost diagnostic filters, preview download persistence after switching back from editing, toolbar interception, missing diagnostic stylesheet imports, overflowing filters/tables, hidden baseline context when comparison controls collapse. Verification: `go test ./...` passed on the final backend changes; dashboard unit, type, lint, build and browser checks are in the [Execution Results design QA](#ux-reviews-2026-09-settings-and-execution-results) entry; browser evidence `09`-`13` (`implemented-*.jpg`).
