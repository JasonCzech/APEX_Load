# WSDL/SOAP Import + Replay: Code Review & Completion Plan

> Status: Historical review snapshot. This file is preserved for audit context
> and should not be treated as current product documentation.

**Scope:** `pkg/convert/wsdl/converter.go` (importer), `pkg/protocol/soap/soap.go` (replay runtime), associated tests and the one shipped sample. Measured against the WSDL 1.1 / SOAP 1.1+1.2 / XSD 1.0 / WS-I BP / OASIS WSS yardstick.

---

## 1. Executive Summary

### WSDL Import — maturity: **early/draft-grade**

The importer parses a single inline WSDL 1.1 document (namespace-agnostic local-name binding) and emits a `dsl.Script{Protocol:"soap"}` with one POST action per operation, a generated document/literal envelope skeleton, and `{{data.wsdl.*}}` placeholder leaf values for human fill-in. It correctly handles the common modern shape: **single-namespace, document/literal, inline-schema, SOAP 1.1, request-only** WSDLs — which is what every existing test fixture is. It honestly surfaces many gaps as `diag` warnings + a `SourceReview` and is explicitly framed as a review draft, not a run-ready artifact.

Everything past that common shape is broken or absent: **rpc/literal and rpc/encoded styles produce a structurally-wrong document envelope; SOAP 1.2 imports ship a SOAP 1.1 envelope namespace; the imported action POSTs to a duplicated URL path (every replay 404s); multi-binding/multi-port WSDLs cannot be targeted; multi-schema namespaces, `elementFormDefault`, type inheritance, `simpleType`/enums, `minOccurs`/`maxOccurs`, attributes-on-the-wire, `wsdl/xsd import/include`, WS-Security, WS-Addressing, and MTOM are all unsupported.** Two of these (URL duplication, 1.2 envelope namespace) make the headline "import a WSDL and replay it" workflow fail end-to-end for the very services it targets.

### SOAP Replay — maturity: **solid core, sharp edges**

The runtime is a thin, well-structured wrapper over `pkg/protocol/http` that owns body shaping, WS-Security UsernameToken injection (PasswordText + PasswordDigest with correct byte-order SHA-1), envelope/Content-Type/SOAPAction defaults for both 1.1 and 1.2, and fault detection with telemetry/extractions. The happy paths (generated-mode envelope wrap, namespace merge/conflict telemetry, UsernameToken, 1.1/1.2 fault flagging) are tested and work.

The defects are concentrated in **fault detection** (the regex-based `detectSOAPFault` scans for `<Value>`/`<Text>`/`faultcode` *anywhere* in the body with no `<Fault>` gate — a critical false-positive that mass-fails healthy SOAP 1.2 responses under the importer's default `fail_on_fault=true`), and a cluster of **interop nits** (unquoted SOAPAction breaks WCF routing; `mustUnderstand="1"` missing on the Security header; TTL=0 ships an already-expired Timestamp; WS-Security silently skipped on default-namespace envelopes). None of these are security or data-loss defects, but several silently break or mis-report replay against real enterprise endpoints.

## 2. Correctness Bugs

Ordered by severity. File:line references are to the current tree.

### CRITICAL

**C1 — Fault detection has no `<Fault>` gate; mass false-positives on healthy responses**
`pkg/protocol/soap/soap.go:622-645` (`detectSOAPFault`)
`detectSOAPFault` scrapes `faultcode`/`faultstring`/`Value`/`Text` from *anywhere* in the envelope. Any successful SOAP 1.2 business response containing a local element named `<Value>` or `<Text>` (extremely common — key/value pairs, settings, datasets) is classified as a fault. The WSDL importer sets `fault_handling.fail_on_fault=true` by default (`converter.go:247`), so such responses are marked `Success=false`, corrupting error-rate/SLA metrics and able to trip goal-based aborts. Even with `fail_on_fault` off, `soap_fault_code/category` telemetry and extractions are poisoned on every success.
**Fix:** First isolate the fault subtree: `faultInner := firstSOAPTagInnerXML(body, "Fault")`; if empty, return `("","","",false)` immediately. Run all `faultcode`/`faultstring`/`Code>Value`/`Reason>Text` extraction against `faultInner` only. The helper already exists. Add regression tests: (a) 200 body with `<Value>`/`<Text>` outside a Fault ⇒ `ok=false`; (b) genuine 1.2 Fault ⇒ correct code/reason; (c) genuine 1.1 Fault.

**C2 — Imported SOAP action POSTs to a duplicated path; every replay hits the wrong URL**
`pkg/convert/wsdl/converter.go:272, 434-443` (`soapActionTarget`) + `pkg/protocol/http/http.go:633-644` (`ResolveURL`)
The importer sets `Config.BaseURL = <full soap:address>` (e.g. `https://host/account`) **and** `action.Target = soapActionTarget(baseURL)` = the path of that same URL (`/account`). At replay, HTTP resolves base+target ⇒ `https://host/account/account` ⇒ 404/connection error for any service whose endpoint has a non-root path (i.e. virtually all). The importer's tests only assert `Config.BaseURL` and never resolve the URL or run `SOAP.Execute`, so the bug is invisible.
**Fix (lowest blast radius):** make the importer emit `action.Target` = the **full** `soap:address` location, so `ResolveURL`'s `http(s)://` short-circuit (`http.go:635`) passes it through unchanged. Also fix the shipped sample `examples/web-api/soap-account-service.json` (target `/account` with base_url `.../account` — same doubling). Add a round-trip test asserting the resolved request URL equals the original `soap:address`.

### HIGH

**C3 — Imported SOAP 1.2 envelope hardcodes the SOAP 1.1 namespace ⇒ VersionMismatch**
`pkg/convert/wsdl/converter.go:455-462` (`soapEnvelope`)
The envelope template hardcodes `xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"` regardless of version. A 1.2 import ships a 1.1-namespaced Envelope with a `application/soap+xml` Content-Type — a contradiction every spec-compliant 1.2 server rejects with `env:VersionMismatch`. The runtime never corrects a pre-formed envelope (`shapeSOAPBody` short-circuits on `looksLikeSOAPEnvelope`, `soap.go:382`), so this is terminal for all 1.2 imports.
**Fix:** give `soapEnvelope` the detected version and select the namespace via the existing `soapEnvelopeURI(version)` (`soap.go:526-531`). Export/share that single 1.1/1.2 URI pair between `pkg/protocol/soap` and `pkg/convert/wsdl` to prevent drift. The `soapenv` prefix string can stay; only the URI varies. Test: 1.2 WSDL ⇒ body contains `http://www.w3.org/2003/05/soap-envelope`; 1.1 ⇒ the xmlsoap URI.

**C4 — rpc-style WSDLs get a document-shaped, mis-namespaced envelope (parsed style is dead)**
`pkg/convert/wsdl/converter.go:195-198, 445-463, 526-554`
`soap:operation/@style` is parsed into `soapOperation.Style` but **never read**. Every rpc/literal and rpc/encoded service imports to a document/literal envelope: wrong wrapper namespace (should be `soap:body/@namespace`, not WSDL TNS), no per-part child elements, extra parts dropped, no diagnostic. Affects legacy Axis1/.NET asmx stacks.
**Fix (full):** parse `@style` on `soap:binding` and `soap:operation`, and `soap:body @use/@namespace` on the binding input. When `style==rpc`: build the Body wrapper from the operation name in the `soap:body @namespace`; iterate **all** input message parts, emitting one unqualified child per `part.Name` populated from `part.Type` (type-based parts like `xsd:int` render a typed placeholder leaf). When `style==document`: keep the current element-driven path. Surface `use=encoded` as an explicit unsupported `Warning`.
**Fix (cheap interim, ship first):** emit a `diag.Warning` whenever a resolved binding/operation style is `rpc` (or `use=encoded`): *"rpc-style binding emitted with document-style envelope; wrapper namespace and part structure need manual correction."* Removes the silent-wrong-output property at near-zero cost.

**C5 — Only the first message part is rendered; multi-part inputs are silently truncated**
`pkg/convert/wsdl/converter.go:528, 556-567` (`inputMessagePart` returns `Parts[0]`)
Any operation whose input message has >1 part imports with a truncated body (missing required elements). rpc operations (inherently multi-part) are worst hit. No diagnostic.
**Fix:** add a `Style` field to `operationInfo` (from `soapOperation.Style`); replace the single-part return with one returning all input parts; in `soapBodySkeleton`/`soapEnvelope` iterate parts (document: each element-part ⇒ Body child; rpc: each part ⇒ child of the operation wrapper); emit a diagnostic when a part can't be rendered. Reuse `messagePartByName` for name-aware matching. Table-driven tests: 2-part rpc message, multi-element-part document message.

**C6 — All elements forced under one `tns` prefix = WSDL TNS; per-schema targetNamespace ignored**
`pkg/convert/wsdl/converter.go:83, 246, 455-462, 570-582, 689-736`
For multi-schema WSDLs (separate types schema with its own `targetNamespace`, the common enterprise shape) every body/header/nested element is bound to the WSDL TNS even when its element actually lives in a different namespace. A schema-validating server (.NET WCF, CXF with validation) rejects the envelope. Cross-namespace local-name collisions resolve to whichever schema is scanned first (`findXSDElement`/`xsdFieldsForType` match local-name only). `xsdSchema.TargetNamespace` is parsed but never used in binding. **No diagnostic is emitted** — invisible to the review workflow.
**Fix:** thread each element/complexType's owning `schema.TargetNamespace` through `findXSDElement`/`xsdFieldsForType`/`renderXSDFields`; allocate a distinct prefix per namespace (`ns1`/`ns2`/…), declare them all on the envelope, prefix each element by its actual namespace; make resolution namespace-aware (prefer same-namespace match before fallback). **Interim:** emit a `diag.Warning` when `>1` distinct schema `targetNamespace` exists in `<types>`.

**C7 — `elementFormDefault` never parsed; nested local elements are always prefix-qualified**
`pkg/convert/wsdl/converter.go:82-88, 708-733`
For `elementFormDefault="unqualified"` schemas (the XSD default), nested local elements must be emitted **unprefixed** (in no namespace). The importer always prefixes them `tns:`, so a validating server rejects `<tns:accountId>` where it expects `accountId`. No diagnostic.
**Fix:** add `ElementFormDefault`/`attributeFormDefault` (`xml:"...,attr"`) to `xsdSchema`; thread the owning schema's form-default into `renderXSDFields`; emit nested **locally-declared** elements without the `tns:` prefix when unqualified. Caveats: (i) a child that is a `ref` to a global element (`field.Ref` branch, L716-723) IS qualified even under unqualified form — gate only on locally-declared (name, not ref) elements; (ii) per-element `@form` can override the schema default (lower-frequency, parse for full correctness). Since the body uses a prefixed `xmlns:tns` rather than a default `xmlns=`, dropping the prefix on locals is safe (no default-namespace conflict).

**C8 — `soap:header` parts from a different namespace emitted under `tns`, losing `soap:header/@namespace`**
`pkg/convert/wsdl/converter.go:188-193, 468-501`
Headers carrying auth/session/routing tokens (the reason `soap:header` bindings exist) are emitted in the wrong namespace ⇒ a `mustUnderstand`/schema-validating server rejects or ignores the token ⇒ auth failure on replay.
**Fix:** in `soapHeaderSkeleton`, resolve the header part's element to its owning schema `targetNamespace`; add `Namespace string xml:"namespace,attr"` to `soapHeaderBinding` and honor `soap:header/@namespace` as an override (rpc); declare a distinct prefix (`h1`/`h2`…) on the envelope instead of forcing `tns`. Requires `findXSDElement` to also return the matched schema's TNS.

**C9 — SOAP version detection is a whole-document substring match for `soap12`**
`pkg/convert/wsdl/converter.go:420-425` (`detectSOAPVersion`)
A raw `strings.Contains(content, "soap12")` flips the whole import to 1.2 on any stray match, and a dual-binding WSDL (1.1 + 1.2, the modern norm) defaults wrong. Combined with C3 this guarantees VersionMismatch. The two substring branches are also redundant: the canonical namespace literal already contains `soap12`, so the bare `|| strings.Contains(content, "soap12")` clause adds only false positives — delete it independently.
**Fix:** determine version per selected binding by inspecting that binding's child `soap:binding`/`soap12:binding` element namespace (`wsdl/soap/` ⇒ 1.1, `wsdl/soap12/` ⇒ 1.2). This is a structural change: the `binding` struct (L173-176) must capture the child soap-binding element's namespace URI, and operations must be associated with their binding (depends on C10). Mitigant: `options.soap_version` override is honored first (L218), so this is "wrong by default," not "impossible."

**C10 — Multiple bindings/ports/services not enumerated; all bindings merged by name, first address wins**
`pkg/convert/wsdl/converter.go:341-386, 388-409`
Real WSDLs expose multiple ports (1.1+1.2, HTTP+HTTPS, internal+external) under one service. The importer merges all bindings keyed by operation **name string** (no `binding/@type` ↔ portType correlation), emits one merged action set, and derives `base_url` from `locations[0]`. Duplicate operation names across portTypes silently clobber; mixed-transport metadata is produced with no warning.
**Fix:** model `binding/@type` and `port/@binding`; enumerate `(service, port, binding)` triples; accept a selection option (service/port/binding name) or default to the first SOAP-bindable port while emitting alternatives as diagnostics; scope operation collection to the chosen binding's portType; derive `base_url` from the chosen port's address. **Interim:** emit a `Warning` when multiple distinct bindings reference the same portType (cheap mixed-transport guard) and when duplicate operation names are clobbered.

### MEDIUM

**C11 — XSD `complexContent`/`simpleContent` extension/restriction inheritance not parsed**
`pkg/convert/wsdl/converter.go:106-112, 614-632`
Derived request types (a `CreatePersonRequest` extending a base `RequestType`, etc. — pervasive in enterprise WSDLs) generate an empty `<tns:Op></tns:Op>` body or a placeholder comment; all inherited and derived fields are missing ⇒ schema-invalid request. Only a generic *"no supported complexType model"* warning fires.
**Fix:** add `ComplexContent`/`SimpleContent` structs to `xsdComplexType` carrying `Extension`/`Restriction` with a base QName + their own `Sequence`/`All`/`Choice`/`Attributes`. In `xsdFieldsForComplexType`, when `complexContent/extension` is present, resolve the base by name (recursively, with the existing depth guard), flatten base elements + the extension's added elements (merge attributes), continue. For `restriction`, use the restriction's restated content model. Base-type resolution must tolerate (and warn on) an unresolvable cross-schema base (imports aren't followed — C16).

**C12 — `simpleType`/enumeration/restriction not parsed; enum/typed fields degrade to string placeholders**
`pkg/convert/wsdl/converter.go:82-88, 601-612, 738-751`
A `Status` of `{ACTIVE,SUSPENDED,CLOSED}` or a `CurrencyCode` gets a free-text `{{data.wsdl.*}}` placeholder with **no diagnostic** listing legal values; a numeric/date `simpleType` loses its base type and renders as a string token instead of `1`/timestamp.
**Fix:** add `xsdSimpleType{Name, Restriction{Base, Enumerations[]}}` to `xsdSchema`. In `placeholderForXSDType`/`xsdFieldsForElement`, resolve named simpleTypes: if enumerations exist, emit the first enum value + a diagnostic listing all allowed values; otherwise recurse on `Restriction.Base` so `xs:int`-restricted simpleTypes reuse the built-in `1` placeholder. Add a converter test with an actual `<xsd:simpleType>` (wholly untested today).

**C13 — Attributes diagnosed but never written to the body; `attributeGroup`/`group`/`anyAttribute` ignored**
`pkg/convert/wsdl/converter.go:614-632, 643-659, 706-713`
`<Order currency="USD">` with `use="required"` imports without the attribute ⇒ server rejects for a missing required attribute. Inline attributes at least produce a naming `Warning` with `(required)`; `attributeGroup`/`group`/`anyAttribute` are not even parsed and drop **silently**.
**Fix:** in `renderXSDFields`, emit at least `use="required"` attributes onto the start tag (`<tns:Order currency="{{data.wsdl.currency}}">`) via `placeholderForXSDType` on the attribute type. Add `AttributeGroup` parsing (inline + `ref=`, resolved against schema-level `<xs:attributeGroup name=...>`) and merge into the owning complexType. Reword the diagnostic to reflect that required attributes are now rendered.

**C14 — `maxOccurs`/`minOccurs`/`nillable` not parsed; arrays render once, optional≡required, no `xsi:nil`**
`pkg/convert/wsdl/converter.go:99-104, 689-735, 733`
`<lineItems maxOccurs="unbounded">` renders exactly one occurrence (schema-invalid if `minOccurs>1`; batch payloads never exercised); optional vs required is indistinguishable; nillable elements can't emit `xsi:nil`. **No diagnostic** signals that an element repeats.
**Fix:** add `MinOccurs`/`MaxOccurs`/`Nillable` (`xml:"...,attr"`, plain strings — `maxOccurs` can be `"unbounded"`) to `xsdElement`. In `renderXSDFields`: when `maxOccurs>1`/`unbounded`, emit 1-2 representative repetitions + a `Warning` naming the element's cardinality; emit `Info` tagging `minOccurs=0` elements optional; emit `xsi:nil` for nillable. The `xsi:nil` path requires declaring `xmlns:xsi` on the envelope (couple with C15).

**C15 — abstract types / `xsi:type` / `substitutionGroup` unsupported; `xsi` namespace never declared**
`pkg/convert/wsdl/converter.go:99-112, 455-462`
Polymorphic schemas (abstract base + concrete subtypes via `xsi:type`, or a substitution-group head) render the abstract type's (often empty) fields with no `xsi:type` ⇒ server rejects (abstract type cannot be instantiated). `xmlns:xsi` is never declared, so even a hand-added `xsi:type`/`xsi:nil` would be a namespace error. Silent — no diagnostic (unlike choice/attributes).
**Fix (minimum viable):** always add `xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"` to the envelope template (L455); parse `Abstract` on `xsdComplexType` and `SubstitutionGroup` on `xsdElement` and emit a `Warning` (*"type X is abstract — choose a concrete xsi:type subtype before replay"*). **Full:** pick a concrete derived/substitution member, emit `xsi:type="tns:Concrete"` + its flattened fields (needs C11).

**C16 — `wsdl:import`/`xsd:import`/`xsd:include` flagged but never resolved**
`pkg/convert/wsdl/converter.go:216, 753-767`
For the common multi-file WSDL, request types live in an imported schema that's never read ⇒ `soapBodySkeleton` falls to the placeholder path and emits `<!-- Review request elements ... -->` bodies. Fails honestly (warnings + visible placeholders) but a single-file submission requirement is a major real-world limitation.
**Fix:** support transitive resolution — accept a bundle/zip of WSDL+XSD, **or** let the user paste/attach referenced schemas for inlined resolution (no network egress). Fetching relative/absolute `schemaLocation` must be SSRF-policy-gated (the codebase already has an SSRF guard under `APEXLOAD_ENV=production`); the zip/paste path is the lowest-risk first increment.

**C17 — Importer never populates WS-Security or transport auth even when the WSDL/policy requires it**
`pkg/convert/wsdl/converter.go:244-248, 468-501`
WSDLs declaring a UsernameToken/Timestamp policy import to scripts with no security header ⇒ replay against a secured endpoint fails with an auth/policy fault. The runtime WS-Security path is fully wired (`config_protocols.go:224-245` → `applySecurity`) but **unreachable from import** — `WSSecurity` stays nil. Similarly no `config.http.auth` for Basic/Bearer.
**Fix:** parse WS-SecurityPolicy assertions (resolve `wsp:PolicyReference` URIs to the `wsp:Policy` block; map `sp:UsernameToken` ⇒ `SOAPConfig.WSSecurity.UsernameToken` with empty placeholder creds + `password_type` from `sp:HashPassword`/`PasswordText`; `sp:IncludeTimestamp` ⇒ `Timestamp`; `sp:TransportBinding` ⇒ diagnostic recommending an https `base_url`). **Minimum:** detect `wsse`/`wsp`/`UsernameToken`/`TransportBinding` markers and emit a `Warning` so the operator knows to add `config.soap.ws_security` before replay.

**C18 — `classifySOAPFaultCategory` substring-matches the raw code, mis-handling namespaced QNames**
`pkg/protocol/soap/soap.go:279-293, 645`
`SOAPFaultCategory` (used in error-taxonomy graphs and client/server SLA splits) is unreliable for namespaced or app-specific codes (`ns:ClientAccountLocked` matches "client"; a `VersionConflict` business code matches "version"). The common real-world case.
**Fix:** strip the namespace prefix (text after last `:`) and compare the local part case-insensitively for **equality** against the closed sets — 1.1 `{Client, Server, VersionMismatch, MustUnderstand}`, 1.2 `{Sender, Receiver, VersionMismatch, MustUnderstand, DataEncodingUnknown}`. Map Client/Sender⇒client, Server/Receiver⇒server, etc.; everything else ⇒ explicit `application` (not `unknown`). Table-driven tests for `ns:ClientAccountLocked`, `ns:AppError`, `VersionConflict`, canonical `soapenv:Server`/`env:Receiver`.

**C19 — SOAP 1.1 `SOAPAction` header emitted unquoted (spec requires a quoted-string)**
`pkg/protocol/soap/soap.go:701-705` + `pkg/convert/wsdl/converter.go:287-289`
Strict 1.1 stacks (WCF/.NET, many ESB/gateways) dispatch on the **quoted** `SOAPAction` and return "action not found" for the bare value. Two call sites set the header (runtime `applySOAPDefaults`, importer), and the runtime skips when the header already exists (`if _, exists` guard) — so **both** must quote.
**Fix:** wrap the value: `action.Headers["SOAPAction"] = "\"" + soapAction + "\""`. Set `SOAPAction: ""` (quoted empty) for 1.1 even when the action is empty (currently gated on `soapAction != ""`, L701). Leave the 1.2 Content-Type `action="..."` path alone. Update `soap_test.go` and the import assertions to expect the quoted form.

**C20 — Timestamp `TTLSeconds=0` produces `Expires==Created` (already-expired)**
`pkg/protocol/soap/soap.go:337-340, 548-555` + `pkg/engine/config_protocols.go:242-244`
Any authored/edited script that enables a WS-Security Timestamp but leaves `ttl_seconds` unset (`omitempty int` defaulting to 0) sends an already-expired timestamp ⇒ every request rejected. No validation/warning. (Not triggered by the importer, which emits no timestamp config — authored scripts only.)
**Fix (defensive pair):** in `appendSOAPConfig` only emit the TTL key when `TTLSeconds > 0`; **and** in `readSecurityConfig` apply a sane default (300s) when timestamp is enabled but `timestampTTL <= 0`, plus a validation warning. Test: `Expires` strictly after `Created` when `ttl_seconds` unset.

**C21 — WS-Security not injected into default-namespace envelopes**
`pkg/protocol/soap/soap.go:419-439` (`applySecurity`)
A hand-authored/recorder-captured raw envelope using a default SOAP namespace (no prefix on Envelope/Header/Body — common in captured traffic) gets **no** WS-Security header ⇒ unauthenticated request ⇒ auth fault, with no diagnostic. (Importer unaffected — it always emits `soapenv:`.)
**Fix:** when `detectEnvelopePrefix` returns `""`, search unprefixed `</Header>`/`<Header>`/`<Body>` anchors and inject an unprefixed `<Header>…wsse:Security…</Header>`. **Critically:** if no anchor is found, emit a diagnostic/fail the action rather than silently returning the unsecured body — silent omission of a required security header is the worst part of the bug.

**C22 — `mergeSOAPNamespaces` only conflict-checks the literal prefix `soapenv`**
`pkg/protocol/soap/soap.go:455-472`
Arbitrary prefix collisions between the config namespace map and the body fragment (same prefix, different URI) produce a syntactically valid but semantically wrong envelope with no warning. Precondition-gated (generated mode + colliding prefix + body not redeclaring), not a default-path failure.
**Fix:** in `detectSOAPBodyNamespaceConflict`, track config + body-local prefix→URI maps and flag any prefix whose body-declared URI differs from the merged-map URI. Generalize the `soapenv`-only URI check to all prefixes.

**C23 — WS-Security injection assumes Header/Body prefix == envelope prefix; mismatched prefixes mis-place or drop security**
`pkg/protocol/soap/soap.go:411-440, 447-453`
For an envelope whose `<Header>`/`<Body>` use a different prefix than the Envelope, security is inserted at the wrong place or not at all (silently). Overlaps C21.
**Fix:** derive the Header/Body prefix from the envelope's own namespace binding — locate the soap-envelope-URI `xmlns` declaration on the Envelope element (prefixed or default) and use the bound prefix (empty for default-ns) to build the match strings. When no insertion site exists, emit a diagnostic / fail rather than returning the unsecured body.

### LOW

- **C24 — `<wsse:Security>` lacks `soapenv:mustUnderstand="1"`** (`soap.go:588`). Servers enforcing WS-SecurityPolicy ignore/reject an un-flagged header ⇒ auth silently skipped. *Fix:* thread the envelope prefix into `buildSecurityHeaderXML`, emit `<prefix>:mustUnderstand="1"`, configurable defaulting to on. (Note: WSS 1.0 does not *mandate* it — scope is strict-policy servers, hence borderline medium.)
- **C25 — `wrapSOAPOperation` wraps generated-mode bodies in an unprefixed, namespace-less operation element** (`soap.go:533-542`). Hand-authored path only. *Fix:* add `OperationNamespace` to `SOAPActionConfig`, emit `<p:Operation xmlns:p="...">`, and replace the substring idempotency guard with a real start-tag match. Updates the pinned `soap_test.go:168` assertion.
- **C26 — `<wsse:Nonce>` omits `EncodingType="...#Base64Binary"`** (`soap.go:575`). Rejected by strict BSP-conformance stacks on the digest path. *Fix:* one-line attribute add; update `soap_test.go:284`; add a digest-path test (none exists).
- **C27 — `replay-1.2-subcode`: 1.2 `<Value>` can grab a Subcode value or unrelated `<Value>`** (`soap.go:630-633, 660-668`). Corrupts fault telemetry (never a false success). Largely subsumed by the C1 Fault-subtree scoping; additionally surface `Subcode>Value` as a distinct `soap_fault_subcode` extraction.
- **C28 — `wsdl2-no-detect-and-report`** (`converter.go:209-211`). WSDL 2.0 fails with a cryptic *"expected element type <definitions> but have <description>"*. *Fix:* lightweight root-element peek before `xml.Unmarshal`; if `XMLName.Space == "http://www.w3.org/ns/wsdl"` or root local-name is `description`, return *"WSDL 2.0 not supported — convert to WSDL 1.1"*; require the WSDL 1.1 namespace on the `definitions` root.

## 3. Completeness Gaps (by area)

### WSDL Binding Model
- **rpc/literal + rpc/encoded styles** (C4): parsed style is dead. A complete impl branches envelope assembly — rpc wrapper in `soap:body/@namespace`, parts as part-named typed children; document keeps element-driven. `use=encoded` (SOAP Section-5: `xsi:type`, `encodingStyle`, multi-ref `href`/`id`, `soapenc:Array`) is WS-I-banned legacy — at minimum parse-and-warn; full wire support is the long tail.
- **Multi-binding/port/service selection** (C10): enumerate `(service, port, binding)` triples; let the user select; carry per-port endpoint and per-binding SOAP version.
- **Non-SOAP `http:`/`mime:` bindings** (`converter.go:173-182, 356-375`): currently treated as SOAP, producing bogus SOAP actions for HTTP-GET/urlEncoded operations. Gate "is SOAP" on the presence of a child `soap:binding`/`soap12:binding`; route or skip-with-warning otherwise. *(medium — operations exposed only via http/mime binding are the broken case; the dual-binding case dedupes by op name.)*
- **`soap:header`/`headerfault` correct generation** (C8): namespace-correct, parameterizable.
- **Output/fault messages**: `operation.Output` is captured but never used; `soap:fault` is unmodeled. Needed for response assertions/correlation.

### XSD Type System
- **Type inheritance** — `complexContent`/`simpleContent` extension/restriction (C11): the single highest-leverage XSD gap.
- **`simpleType` + enumeration/pattern facets** (C12): drive valid placeholders/pick-lists and correct base-type defaults.
- **Cardinality** — `minOccurs`/`maxOccurs` arrays + optionality (C14).
- **`nillable` / `xsi:nil`** (C14, coupled to xsi-namespace declaration).
- **Attributes on the wire + `attributeGroup`/`group`/`anyAttribute`** (C13).

### [CRITICAL] soap-fault-no-fault-element-gate  _(correctness-bug · fault-and-response)_
**detectSOAPFault never checks for a <Fault> element — scrapes Value/Text/faultcode/faultstring anywhere in the envelope, producing false faults on successful business payloads**

- **file:** `pkg/protocol/soap/soap.go:622-645`
- **impact:** With fail_on_fault enabled (which the WSDL importer sets by default — converter.go writes fault_handling.fail_on_fault=true), real load tests against SOAP 1.2 services whose responses legitimately contain Value/Text elements report mass false failures, corrupting SLA/error-rate metrics and triggering goal-based aborts. Even with fail_on_fault off, SOAPFaultCode/Category telemetry and the soap_fault_* extractions are populated with garbage on every successful response.
- **fix:** Require a <Fault> element before scraping: first locate the <[ns:]Fault>...</Fault> region (e.g. via firstSOAPTagInnerXML(body,"Fault")) and run faultcode/faultstring/Code-Value/Reason-Text extraction ONLY within that substring. Return ok=false when no Fault element is present. This also naturally scopes the 1.2 Value/Text lookup to the fault subtree.
- **verifier:** Severity critical is justified: WSDL-imported SOAP 1.2 scripts default to fail_on_fault=true (converter.go:247), so services whose successful responses legitimately contain locally-named Value/Text elements (extremely common: key/value pairs, settings/config responses, ADO/dataset payloads) get mass false failures, corrupting error-rate/SLA metrics and able to trip goal-based aborts. Even with fail_on_fault off, soap_fault_code/category telemetry+extractions are poisoned on every successful response. Sharper fix note: the firstSOAPTagInnerXML(body,"Fault") helper already exists and is the right primitive — extract the Fault subtree once, then run faultcode/faultstring and Code/Value + Reason/Text scraping only within that substring; if no Fault subtree is found, return ok=false immediately. Bonus correctness improvement: SOAP 1.2 fault code lives in env:Code/env:Value and reason in env:Reason/env:Text — scoping to the Fault subtree also stops the current code from grabbing an unrelated top-level Value/Text even inside a genuine fault envelope.
