## Verdict

**48 confirmed findings: 1 critical, 8 high, 19 medium, 20 low.** The change set should not ship as-is. Recurring themes:

1. **Correlation work limits fail closed on realistic data** — the new deterministic budgets (quadratic `DetectChecked` accounting, 1024 JSON candidates/response, 8192 `&`-separators, 8192 Salesforce JSON tokens) are exceeded by ordinary captures (a single 2000-record SOQL page, a 258KB JSON response, a large HTML page), and most call sites treat the limit as fatal: HAR/sample import 400s, Salesforce Analyze returns nil review silently, browser-to-HTTP preview 422s, diagnose/rulesets 422. The degrade-to-warning pattern exists in this same change set (`pkg/recorder/converter.go:73-76`) but only the recorder uses it.
2. **Upgrade data loss** — first boot deletes every legacy recording baseline (no backfill for `script_incarnation`), and separately all v1/v2 ciphertext is rejected on read with no migration.
3. **Flagship save flow broken** — the browser-recorder Save path now always 409s (the server demands the conversion endpoint; the dashboard panel was never updated).
4. **Java Vuser persistent-lifecycle regressions** — transient start failures permanently poison VUsers; helper classes with `init()` block promotion; init-at-once groups discard the state persistence exists to preserve; availability checks fail previously-working deployments.
5. **Blocking I/O under process-wide or manager-wide locks** in the new HA lease plumbing — DB round-trips (up to 5s each) under `replaySessionMu` / manager mutexes serialize or freeze the whole replay/debug surface during DB latency.

#### 4. DetectChecked search-byte budget is quadratic in candidates and hard-fails realistic recordings

`pkg/convert/correlate/correlate.go:190` · found by: correlate-core
