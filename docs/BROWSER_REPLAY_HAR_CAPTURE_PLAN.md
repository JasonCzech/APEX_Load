# Browser Replay HAR Capture Plan

## Summary

Add HAR export support to browser replay in two phases. V1 produces a practical HAR 1.2 artifact from enriched replay evidence and works across the current browser engines. V2 adds native Playwright HAR recording where the runtime can support full-fidelity browser capture.

Browser replay remains a diagnostic canary workflow. HAR capture is evidence for debugging, migration review, and browser-to-HTTP conversion, not a high-density browser load claim.

## V1: Synthetic HAR From Replay Evidence

V1 should generate a `replay.har` artifact from browser replay events without adding a new required backend endpoint.

Key changes:

- Build a backend HAR writer that converts replay `network_entries` across all browser replay events into a HAR 1.2 `log.entries` document.
- Include `replay.har` in the existing browser replay ZIP export whenever browser network evidence exists.
- Add a `Download HAR` action to the Browser Replay cockpit that exports the generated HAR for the current replay report/session.
- Add artifact metadata such as HAR availability, entry count, and fidelity label without breaking existing replay response shapes.
- Preserve existing `network_entries`, console evidence, screenshots, DOM summaries, and replay ZIP contents.

Chromium CDP enrichment is part of V1:

- Extend the Chromium CDP request tracker to retain request ID, URL, method, resource type, request headers, optional post body, response status, status text, response headers, MIME type, encoded/body size, timing, start time, and failure text.
- Correlate `RequestWillBeSent`, `ResponseReceived`, `LoadingFinished`, and `LoadingFailed` events by CDP request ID.
- Preserve redirect chains as distinct HAR entries when CDP emits separate request lifecycle events.
- Add defensive behavior for partial event streams, such as request-without-response, response-without-finish, and failed requests.
- Keep live replay payloads bounded by storing enriched fields as optional evidence and exporting the heavier HAR document through artifact/export flows.

## V2: Native Playwright HAR Recording

V2 should add native HAR recording for browser contexts where Playwright can own the context lifecycle.

Key changes:

- Use Playwright-Go `RecordHarPath`, `RecordHarMode`, `RecordHarContent`, `RecordHarOmitContent`, and URL filtering options for Playwright-backed replay contexts.
- Save native HAR output when the browser context closes, then include it in replay export bundles.
- Label exported HAR fidelity as `native` when generated by Playwright and `synthetic` when generated from replay evidence.
- Decide whether Chromium browser replay should move from chromedp to Playwright to share native HAR capture with WebKit. If Chromium stays on chromedp, keep V1 synthetic HAR as the Chromium implementation and document the fidelity difference.
- Add size guardrails for native HAR captures, including content mode defaults, static asset filtering, and clear UI warnings when exports may be large.

## Interfaces And Compatibility

V1 should be backward compatible:

- Extend Go and TypeScript browser replay network entry types only with optional fields.
- Extend replay artifact manifests only with optional HAR metadata.
- Do not require clients to request HAR capture for existing replay/debug flows.
- Do not change existing browser replay start, pause, resume, stop, or session read endpoints.
- Keep the current browser replay ZIP export valid for clients that ignore new HAR files.

V2 may add optional browser replay start payload fields for native HAR capture settings, but defaults should preserve current replay behavior.

## Test Plan

Go tests:

- Unit-test Chromium CDP enrichment for successful requests, failed requests, redirects, missing responses, missing finish events, headers, timing, and size fields.
- Unit-test HAR generation for valid HAR 1.2 structure, entry ordering, request/response mapping, timing mapping, failure mapping, and empty network evidence.
- Extend replay artifact manifest tests for HAR availability and entry counts.
- Add Playwright-native HAR tests in V2 around context options, context close behavior, native file availability, and export bundle inclusion.

Dashboard tests:

- Verify Browser Replay cockpit shows `Download HAR` only when network evidence exists.
- Verify browser replay ZIP export includes `replay.har`.
- Verify empty/no-network replay sessions show a clear disabled or unavailable HAR state.
- Verify HAR metadata/fidelity labels render without breaking existing screenshot, console, network, DOM, and Core Web Vitals previews.

Validation:

- Run focused Go tests for `pkg/protocol/browser`, replay/HAR builder code, and API export code.
- Run focused dashboard tests for `BrowserReplayDebugger` and `ScriptEditor`.
- Run `go test ./...`.
- Run `npm run build` in `dashboard`.
- Smoke-test in the in-app browser: open a browser script in Script Editor Debug, run Browser Replay, confirm cockpit evidence, HAR availability, ZIP export, and responsive layout.

## Assumptions

- V1 prioritizes low-risk all-engine HAR export over perfect DevTools HAR parity.
- V1 synthetic HAR may omit response bodies unless body capture is already available or can be added without bloating live replay streams.
- Chromium CDP network capture enrichment is required in V1.
- Native full-fidelity HAR recording is V2 because the current Chromium replay path uses chromedp while WebKit uses Playwright.
- Browser replay HAR artifacts are diagnostic/export artifacts and should not be pushed through hot-path live WebSocket messages.
